# C 语言任务工坊：从第一行代码到独立维护项目

这是一门围绕 **C17 命令行任务管理器** 展开的项目课程。你会把“添加一条学习任务”逐步做成可验证、可保存、能处理错误的程序，再用同一组数据练习算法和高级主题。

先说范围：C 的核心语言可以系统学习；操作系统接口、芯片外设、网络、图形、数据库以及每一个行业库，无法由一个项目全部覆盖。本课程把内容标成三层：**核心必修**要能亲手实现，**工程进阶**要能解释并验证，**专题选学**提供边界和后续实验。完成的标准是能写、能解释、能排错，不是把术语看完。

## 学习方式与项目地图

第一次只读第 1 章，运行程序，然后按章节推进。每章依次完成：预测 → 运行 → 修改 → 测试 → 用自己的话说明原因。遇到指针先画对象和箭头；遇到错误先保留最小复现，别靠反复改代码碰运气。

| 文件或目录 | 学习时关注的问题 |
|---|---|
| `src/main.c` | 命令怎样进入程序？界面与业务怎样分工？ |
| `src/input.c`、`include/input.h` | 一整行输入如何变成可靠的数字或命令？ |
| `src/task.c`、`include/task.h` | 任务、容器、增删改查、容量和所有权有哪些约定？ |
| `src/storage.c`、`include/storage.h` | 内存中的任务怎样变成文件，坏文件怎样处理？ |
| `tests/test_core.c` | 哪些行为可以重复验证，哪些边界曾经出错？ |
| `lessons/` | 把一个语言概念拆成可独立运行的小程序。 |
| `exercises/` | 在项目之外先完成的小练习，再迁回项目。 |

构建和运行命令以项目根目录的 `README.md` 为准。本文代码块若未写完整的 `#include` 和 `main`，就是**解释用片段**，应放进对应示例或自己的完整小程序；不要把所有片段一起粘进同一个文件。建议把学习记录写成“我原来预测什么，实际是什么，为什么”。

渐进版 `stages/01_task_card.c → 02_fixed_list.c → 03_menu.c` 展示一个任务如何变成固定列表和交互程序。初学时先顺着这三步走，再打开完整模块；这些教学阶段不具备最终程序的所有错误处理能力。

## 第 1 章　让程序真正运行：源文件、编译、链接

**层级：核心必修。目标：**知道 `.c` 是文本，编译器把它翻译为目标文件，链接器解决跨文件符号并生成可执行程序；能区分编译错误、链接错误和运行错误。

**项目情境：**先运行任务工坊，添加一个“学 C”任务、列出它并退出。然后阅读 `src/main.c`，只追踪程序从入口到退出的路线，暂时不钻进每个函数。

从这个完整程序开始：

```c
#include <stdio.h>

int main(void)
{
    puts("C Task Lab");
    return 0;
}
```

`#include` 让编译器看到标准库声明；`puts` 输出字符串和换行；`return 0` 表示程序成功结束。C17 中 `int main(void)` 明确表示不接收参数；需要命令行参数时用 `int main(int argc, char *argv[])`。不把 `void main()` 当作本课程写法。

典型 GCC/Clang 流程是 `cc -std=c17 -c hello.c`，再 `cc hello.o -o hello`。驱动程序也能一次完成两步。预处理会处理包含和宏，编译/汇编产生目标文件，链接把它们组合起来。Windows 可执行文件通常有 `.exe` 后缀，命令细节看 README。

**预测与动手：**先预测输出，再删除一处分号、把 `puts` 写成 `putss`、最后恢复并运行。记录每个错误发生在哪一步；如编译器只警告隐式声明，仍要当错误修复。

**验收：**能从源代码重新构建；能解释“找不到可执行文件”和“未定义的函数符号”不是同一个问题；知道只改 `.c` 不会自动改变旧的可执行文件。

**参考提示：**正确输出是 `C Task Lab` 加换行；分号错误通常在编译阶段；声明存在但没有定义的函数通常在链接阶段失败。具体诊断文本由编译器决定。

## 第 2 章　类型、对象、表示范围与转换

**层级：核心必修。目标：**区分声明、初始化、赋值；理解整型、浮点型、`char`、`_Bool`/`bool`、`size_t`；按范围选类型，不背“int 永远 4 字节”。

**项目情境：**任务有 ID、优先级、完成状态，容器有数量。这些含义不同，不能因为都能写成数字就混用。

```c
int completed = 2;
int total = 3;
double ratio1 = completed / total;
double ratio2 = (double)completed / total;
printf("%.2f %.2f\n", ratio1, ratio2);
```

整数除法先发生，事后放进 `double` 不会补回小数。转换要放在运算之前。有符号整数超出表示范围可能触发未定义行为；无符号运算按其范围取模，也不代表业务上合法。窄化赋值要先检查范围。`float`、`double` 通常近似表示十进制小数，金额类需求不能直接假设 `0.1 + 0.2` 精确等于 `0.3`。

`sizeof` 返回 `size_t`，打印用 `%zu`；`int` 用 `%d`，`unsigned` 用 `%u`，`long` 用 `%ld`，`double` 用 `printf` 的 `%f`。`scanf` 的规则不同，例如读 `double *` 用 `%lf`。格式与实参不匹配可能是未定义行为。`<limits.h>`、`<float.h>` 查询范围；`<stdint.h>` 的精确宽度类型只在实现支持该宽度时存在；对应打印宏在 `<inttypes.h>`。

**预测与动手：**预测上面两项；打印 `sizeof(char)`、`sizeof(int)`、`INT_MAX`；给优先级验证范围（本项目低/普通/高分别为 1/2/3）。再解释为什么 `-1 < 1u` 不能按纯数学直觉判断。

**验收：**能修复整数除法截断；不假设地址可放进 `int`；知道 `sizeof(char)` 恒为 1，但一个 C 字节不由标准保证恒为 8 位，要看 `CHAR_BIT`。

**参考提示：**输出 `0.00 0.67`。在 `-1 < 1u` 中，通常算术转换使 `-1` 转为 `unsigned int` 的最大值，比较为假。先检查非负，再转换为计数类型。

## 第 3 章　表达式、分支、循环和位运算

**层级：核心必修。目标：**正确使用算术、比较、逻辑、赋值、条件运算符；会写带终止条件的循环；区分 `&&` 与 `&`。

**项目情境：**命令分发使用 `if` 或 `switch`，列表使用循环，按状态筛选使用条件表达式。先让一个循环正确处理 0 项、1 项和多项。

```c
unsigned flags = 0u;
const unsigned DONE = 1u << 0;
const unsigned PINNED = 1u << 1;
flags |= DONE | PINNED;
flags &= ~DONE;
printf("%u %d\n", flags, (flags & PINNED) != 0u);
```

`&&` 和 `||` 从左到右短路求值，因此 `p != NULL && p->done` 会先检查指针。按位 `& | ^ ~ << >>` 处理整数位，不替代逻辑运算。移位优先练无符号类型，移位数量必须非负且小于提升后左操作数的位宽；不要用负数移位或位宽大小的移位数做猜测实验。

`=` 是赋值，`==` 是比较。`switch` 的 `case` 不自动结束，通常需要 `break`；`break` 只退出最近的循环或 `switch`，`continue` 进入下一轮。优先级决定表达式如何结合，**不普遍决定操作数的求值顺序**。把多个 `i++` 挤在一个表达式里容易形成未定义行为；拆成语句更清楚。

**预测与动手：**预测片段输出；写循环打印 1 到 5，只跳过 3；故意把条件 `i < count` 写成 `i <= count`，不用执行就指出越界发生在哪里。阅读程序的退出条件。

**验收：**空列表不会访问数组；非法命令不陷入死循环；能解释 `%` 的用途、除数不能为 0，并能用括号表达筛选意图。

**参考提示：**片段输出 `2 1`。循环应打印 1、2、4、5。访问 `items[count]` 已越过最后一项；最后合法下标是 `count - 1`，前提是 `count > 0`。

## 第 4 章　函数、参数、作用域和生命周期

**层级：核心必修。目标：**用函数拆分职责；理解值传递、返回值、函数原型、作用域、链接与存储期是不同维度。

**项目情境：**把“判断优先级是否合法”从界面中提取出来，让交互和测试都能调用。头文件声明接口，源文件给出实现。

```c
static int clamp_priority(int p)
{
    if (p < 1) return 1;
    if (p > 3) return 3;
    return p;
}

int value = 9;
printf("%d %d\n", clamp_priority(value), value);
```

C 的函数参数是值传递：函数拿到实参值的副本。想修改调用者对象，要传它的地址；这仍然是传递“指针值”的副本。不要返回局部自动对象的地址，函数结束后该对象生命周期结束。

块内普通局部对象通常具有自动存储期；文件作用域对象与 `static` 局部对象具有静态存储期；`malloc` 获得的对象在释放前有分配存储期；线程存储期留到第 21 章。块内 `static` 对象跨调用保留值；文件作用域的 `static` 函数/对象具有内部链接。作用域回答“名字在哪里可见”，生命周期回答“对象何时存在”，链接回答“多个声明是否指同一个实体”。不要把“全局”当成对这三件事的完整解释。

**预测与动手：**预测输出；新增 `is_valid_priority(int)`，对 0、1、3、4 返回真假。比较两种业务策略：拒绝非法优先级、自动截到边界；说明两者对用户的影响。上面的截断函数只是值传递实验，主项目对范围外优先级选择拒绝。

**验收：**函数有明确输入、输出和失败约定；声明与定义一致；能指出一个局部变量的可见范围和生命周期。

**参考提示：**输出 `3 9`。验证函数可返回 `p >= 1 && p <= 3`。带状态的静态局部计数器会影响测试间独立性，优先把业务状态放进显式容器。

## 第 5 章　数组、字符串与 UTF-8 边界

**层级：核心必修。目标：**区分数组容量、有效长度、字符串长度；掌握 `\0`、下标边界、`sizeof`、`strlen`、基本字符串函数。

**项目情境：**任务标题是一串字节。用户输入中文时，“最多 95 个字节”和“最多 95 个汉字”不是同一需求。真实的 `Task.title[96]` 保留 1 字节给终止符；业务拒绝空标题、ASCII 控制字符和 DEL。程序按字节存储，不验证输入是不是合法 UTF-8，也不计算屏幕字符数；正常中文显示仍依赖输入、编译和终端编码配合。

```c
char title[8] = "learn";
printf("%zu %zu\n", sizeof title, strlen(title));
title[0] = 'L';
puts(title);
```

字符串以第一个零字节终止；容量包含存放终止符的位置。`char s[3] = {'a', 'b', 'c'};` 是数组但不是可直接传给 `puts` 的字符串。`"abc"` 还包含结尾的 `\0`。`char s[] = "abc"` 得到可修改数组；不要修改字符串字面量，通过 `const char *s = "abc"` 表达只读使用。

数组不是指针，但多数表达式中会转换为首元素指针；在数组对象本身上做 `sizeof` 可得整个数组大小，在函数的 `char a[]` 形参中它已经调整为指针。比较字符串内容用 `strcmp`，不是 `==`。复制前检查目标容量；`strncpy` 不保证总有结尾零，不能当作通用安全版 `strcpy`。

在约定输入/文件为 UTF-8 时，`strlen` 数字节；`u8"中文"` 在 C17 的 UTF-8 字符串内容占 6 个字节，结尾零另占 1 个字节。普通 `"中文"` 的执行编码还取决于编译环境。按字节截断可能切开 UTF-8 序列；按用户看到的字符计数还涉及码点、组合字符和显示宽度，标准库的 `strlen` 不解决这些问题。

**预测与动手：**预测输出；手写有容量参数的字符串复制练习，要求目标不足时明确失败。输入一个长中文标题，确认项目是拒绝、截断还是接受；不能把乱码当作成功。

**验收：**能画出 `title` 的 8 个字节；所有字符串接口交代容量；能说明本项目标题限制的单位。

**参考提示：**输出 `8 5`，然后 `Learn`。所需空间为 `strlen(source) + 1`；检查后再复制，包括终止符。对不可信输入，不应在确认边界前无限扫描它。

## 第 6 章　可靠输入：从一行文本到一个数字

**层级：核心必修。目标：**理解 `fgets` 的有界读取和 `fgetc` 的逐字节读取，使用 `strtol/strtoul` 和结束指针验证数字；区分 EOF、空行、格式错误、范围错误和过长行。

**项目情境：**用户把 ID 输入为 `12abc` 或输入一个超大的整数时，程序应解释问题并保持任务不变。

```c
/* 片段：还需检查尾部空白与目标业务范围。 */
errno = 0;
char *end;
long value = strtol(text, &end, 10);
if (end == text) {
    /* 没有读到数字。 */
} else if (errno == ERANGE) {
    /* 超出 long 的范围。 */
} else {
    /* 跳过尾部空白，要求剩余内容为空，再检查 value。 */
}
```

需要 `<errno.h>`、`<stdlib.h>`；用 `isspace` 处理字节时传 `(unsigned char)*end`，因为除 `EOF` 外，`ctype.h` 函数只接受可表示为 `unsigned char` 的值。`strtol` 可接受前导空白与符号；业务是否允许负号必须另外决定。`errno` 不是每次调用都会自动清零，也不是任何函数失败都会设置它。

`fgets(buffer, sizeof buffer, stdin)` 最多读取容量减一的字节并加终止符，成功时可能保留换行。没读到换行可能表示长行，也可能是文件末尾的最后一行；要按接口约定继续检查/消费剩余内容。若拒绝长行，要丢弃该行剩余字节，否则下一轮会误当新命令。不要用 `fflush(stdin)` 清输入；这不是 ISO C 的可移植用法。

上面是**宽松解析实验**，若主动跳过尾部空白，可以接受 ` 42 `。主项目的 `input_ulong` 有更严格的合同：只接受非空的 ASCII 十进制数字串，再用 `strtoul` 检查范围，拒绝空白、正负号与垃圾后缀。主项目 `input_line` 逐字节调用 `fgetc`（结果放在 `int` 中）来识别嵌入 NUL、消费过长行并处理 CRLF；不要把它误认为直接调用 `fgets`。

**预测与动手：**为输入解析列出 `42`、` 42 `、`42x`、空串、`-1`、超大数的结果。找到 `src/input.c` 实际处理这些情况的分支。

**验收：**混合数字与字母不被悄悄接受；EOF 能正常退出；长行不会污染下一条命令；失败后不改变旧值。

**参考提示：**若宽松实验约定业务范围为 0–100，`42`、` 42 ` 成功，其余失败；`-1` 能被 `strtol` 解析，但被业务范围拒绝。主项目严格策略只有 `42` 成功，` 42 ` 也拒绝。业务范围检查放在确认解析完整之后；只有检查通过才转成目标类型。本项目 `strtoul` 的结果类型已是 `unsigned long`，仍须检查所要求的最小/最大值。

## 第 7 章　指针：对象的位置、借用和边界

**层级：核心必修。目标：**理解 `&`、`*`、空指针、指针算术、`->`，能画出一个容器及其元素的地址关系。

**项目情境：**按 ID 找到任务后修改完成状态。查找函数返回的地址通常只是借给调用者使用，不表示调用者获得释放权。

```c
int values[] = {10, 20, 30};
int *p = &values[1];
*p += 5;
printf("%d %d\n", values[1], *(values + 2));
```

`p` 是一个装着地址值的对象，`*p` 是它指向的对象。指针加一跨过一个指向类型的元素，不是总跨一个字节。只在同一数组及其尾后位置内进行这里的遍历算术；尾后指针可比较/作为循环边界，不能解引用。无效、空、悬空指针都不能解引用；`free` 后把一个变量设成 `NULL` 不会修好其他别名。

`const Task *p` 表示不能通过 `p` 修改任务；`Task *const p` 表示这个指针变量不能改指向；两者可以组合。`const` 不是内存寿命保护。动态数组扩容成功、元素删除移动或排序之后，之前取得的元素指针可能失效或指向不同任务。跨操作保存 ID，操作后重新查找，通常比保存内部地址稳妥。

打印对象指针用 `printf("%p", (void *)p)`，不猜地址大小。C 标准不保证对象指针与函数指针能随意互转。

**预测与动手：**预测输出；写 `void increment(int *value)` 并解释调用为什么用 `&count`；追踪任务查找返回值在哪些操作后不能再依赖。

**验收：**每次解引用前能说出指针指向谁、对象是否仍活着、是否在范围内；不返回局部数组地址。

**参考提示：**输出 `25 30`。可让 `increment` 明确要求非空，并在内部 `++*value`；若接口允许空，则先处理空。接口约定必须统一，不能只靠调用者猜测。

## 第 8 章　多级指针、二维数组和函数指针

**层级：工程进阶。目标：**能阅读 `T **`、指向数组的指针和回调声明；知道它们并非可互换的“更高级地址”。

**项目情境：**一个函数若要替换调用者的缓冲区地址，需要拿到指针变量的地址；排序库则通过函数指针调用你的比较规则。

```c
static int compare_int(const void *left, const void *right)
{
    int a = *(const int *)left;
    int b = *(const int *)right;
    return (a > b) - (a < b);
}

/* int items[] = {3, 1, 2}; */
/* qsort(items, 3, sizeof items[0], compare_int); */
```

比较器返回负数、零、正数，不要求精确为 -1、0、1。这里不用 `a - b`，避免相减溢出。`qsort` 不保证稳定性，也没有由 C 标准承诺某个具体复杂度；需要稳定排序时另选算法。

`char **out` 指向一个 `char *` 对象，可以通过 `*out` 更新它。`int matrix[2][3]` 连续存两行数组，转换后是 `int (*)[3]`，不是 `int **`；两者布局和解引用规则不同。`const char **` 也不能由 `char **` 随意转换，这会破坏只读约束。命令行 `argv` 是指针数组的接口，不等同于固定列数二维字符数组。

**预测与动手：**手动追踪数组排序后顺序；给 `int (*operation)(int, int)` 配一个求和函数；画出二维数组与“每行单独分配”的指针数组两种内存图。

**验收：**能从变量名向外读声明；回调签名完全匹配；不靠强制转换掩盖不兼容的函数指针或二维数组类型。

**参考提示：**排序后为 1、2、3。函数指针中的括号很重要：`int *operation(int, int)` 声明的是返回指针的函数。多级指针练习必须写清谁分配、谁释放。

## 第 9 章　用结构体表达任务：enum、union 与布局

**层级：核心必修。目标：**使用 `struct`、`enum`、`typedef`、指定初始化；理解结构赋值、浅拷贝、对齐和填充；知道 `union` 的适用范围。

**项目情境：**把 ID、标题、优先级、状态放进一个任务类型，避免维护几组必须同步下标的平行数组。

```c
typedef enum { TODO, FINISHED } State;
typedef struct {
    unsigned id;
    int priority;
    State state;
} SmallTask;

SmallTask a = {.id = 7u, .priority = 2, .state = TODO};
SmallTask b = a;
b.priority = 3;
printf("%d %d\n", a.priority, b.priority);
```

结构赋值复制成员值；若成员本身是指针，复制的是地址，不会自动复制它指向的堆内存。真实项目的 `Task` 定义以 `include/task.h` 为准。C17 的枚举是整型的一种，但不保证像带运行时检查的“封闭选择类型”；读取文件后仍要验证枚举值。

结构体可能为了对齐在成员间及末尾加入填充，因此 `sizeof(struct)` 不必等于成员大小之和。用 `offsetof` 和 `_Alignof` 观察当前实现，不把观察结果写死成跨平台协议。比较两个任务的意义应逐成员定义，不用 `memcmp` 比较可能含填充的整个结构。

`union` 的成员共享存储，通常用“枚举标签 + 联合体”表示几种事件中的一种。标签必须与当前有效成员配套。通过其他成员重解释表示有细致的可移植性限制，初学时不要把它当作无条件安全的类型转换；复制对象字节可用 `memcpy`，语义仍需另行定义。位域布局也不适合直接当磁盘或网络格式。

**预测与动手：**预测输出；为“添加/删除/完成”命令设计带标签的事件；打印自己结构体的大小与成员偏移并解释填充。

**验收：**能区分结构的值拷贝与指针所有权拷贝；不假设结构二进制表示可直接持久化；每次处理联合体先检查标签。

**参考提示：**输出 `2 3`。如果标题是独立分配的 `char *`，`b = a` 后两者共享一块标题内存；直接各自 `free` 会重复释放。本项目标题内嵌于 `Task`，所以不为每个标题单独分配内存。

## 第 10 章　动态数组、realloc 与所有权

**层级：核心必修。目标：**使用 `malloc`、`calloc`、`realloc`、`free`；区分有效数量 `len` 与槽位容量 `cap`；处理分配失败和乘法溢出。

**项目情境：**任务数超过初始容量时扩容。失败应该保留旧任务，而不是丢失旧指针或留下半条任务。

```c
/* 假定 items 为 int *，new_cap > 0。需要 <stdint.h>。 */
if (new_cap > SIZE_MAX / sizeof *items) {
    /* 大小计算会溢出：报告失败。 */
} else {
    int *grown = realloc(items, new_cap * sizeof *items);
    if (grown != NULL) {
        items = grown;
        cap = new_cap;
    } else {
        /* items 与 cap 仍保留原值。 */
    }
}
```

不要直接 `items = realloc(items, bytes)`：非零大小分配失败时会把唯一旧地址覆盖成 `NULL`，造成泄漏。成功后只能依赖返回的新地址；旧别名不能继续使用，即使数值地址看起来没变。扩容倍增前也要检查容量加法或乘法溢出。新获得的区域不自动初始化；`calloc` 按字节清零，也不应由此假设所有指针或浮点类型的语义零都能由全零字节表示。

“所有权”不是 C 的自动功能，而是项目约定：谁负责释放，谁只是借用。每次成功分配最终恰好对应一次释放；`free(NULL)` 合法；重复释放、释放非分配地址、释放后使用都不合法。零大小分配的细节跨标准有变化，本项目显式避免 `realloc(p, 0)`，空容器通过 `free` 后重置字段实现。

**预测与动手：**画出空容器、装满、扩容成功、扩容失败四个状态；连续添加跨过两次容量边界，再全部删除；检查清理函数能否处理空容器。

**验收：**始终满足 `len <= cap`；失败不改变已保存的任务；退出时释放全部拥有的资源；知道删除元素是否也要释放内部成员。

**参考提示：**先取得新资源，再提交新状态。若 `Task` 内嵌固定字符数组，移动结构即可复制标题内容；若内部是指针，则需要额外的生命周期设计。

## 第 11 章　多文件项目、头文件和接口

**层级：核心必修。目标：**理解声明与定义、翻译单元、外部/内部链接、包含保护、`static` 辅助函数；能定位重复定义与缺失定义。

**项目情境：**界面只负责交互，任务模块维护不变量，存储模块读写文件。一个模块不需要知道另一个模块的全部内部细节。

```c
/* counter.h */
#ifndef CTL_COUNTER_H
#define CTL_COUNTER_H
int next_number(void);
#endif

/* counter.c：示意，实际要另存一个源文件。 */
/* #include "counter.h" */
int next_number(void)
{
    static int number = 0;
    return ++number;
}
```

头文件通常放类型定义、宏和函数声明，源文件放普通外部函数定义。把普通函数定义放进被多个源文件包含的头文件，会产生多重定义问题。若确实需要全局对象，头文件写 `extern int count;`，恰好一个 `.c` 写定义；本项目更适合把状态放入容器对象再传参。

每个 `.c` 应包含自己的接口头文件，让编译器核对签名。头文件应能独立包含，自己包含所需的标准头。不要 `#include "task.c"` 来逃避链接。头文件保护阻止同一翻译单元重复展开，不会把所有源文件“合成一次定义”。`static inline` 的头文件小函数属于进阶写法，先理解普通函数再使用。

**预测与动手：**独立编译每个 `.c` 再链接；漏掉 `storage.c` 看诊断；把一个辅助函数设成 `static`，解释为何其他 `.c` 不应直接调用它。

**验收：**能沿 `main → 输入/业务 → 存储` 追踪依赖；公开接口尽量少；头文件不依赖偶然的包含顺序。

**参考提示：**漏掉实现文件通常产生链接错误。若编译直接报告未知类型，先查声明、包含和拼写，不能靠反复调整链接参数解决。

## 第 12 章　实现任务业务：不变量、ID 和状态提交

**层级：工程进阶。目标：**把“可以运行”提升为“所有分支都有清楚约定”；写添加、查找、完成、删除、筛选与统计。

**项目情境：**删除第 2 项以后，其他任务的 ID 不应该因为下标变化而改名；无效操作不能破坏原列表。

先从 `include/task.h` 抄下真实容器字段：`Task *items`、`size_t len`、`size_t cap`、`unsigned long next_id`。不变量是有效元素在 `[0, len)`；`len <= cap`；每个标题和优先级有效；ID 唯一且小于 `next_id`。ID 是身份，下标是位置，排序或删除都会改变位置。本项目保留单调增长的下一个 ID，删除不回收编号；当 `next_id == ULONG_MAX` 时拒绝再添加，避免编号回绕。

```c
/* 按保持顺序的方式删除下标 index；前提 index < len。 */
for (size_t i = index + 1; i < len; ++i) {
    items[i - 1] = items[i];
}
--len;
```

这是连续数组的一种删除策略，移动成本与后续元素数量相关。若元素持有堆资源，删除前要释放被删元素拥有的资源，移动后尾部旧槽不能再作为第二个所有者释放。项目的固定数组标题与指针标题方案要分清。

业务函数返回结果，界面决定如何显示。不要在可测试业务函数里把所有错误都 `exit` 掉。添加流程应先验证，再准备容量，再写元素，最后增加数量；失败分支不提前增加 `len`。所谓“提交”就是让状态只在操作成功后变为新状态。`task_find` 返回只读借用指针；修改任务使用 `task_set_done/task_set_urgent`。`task_visit` 回调执行期间不能增删、排序、释放列表，也不能让当前元素地址失效。

**预测与动手：**列出三项 ID 为 1、2、3；删 ID 2，预测剩余 ID 和下标；尝试删除不存在的 ID、重复完成同一任务、添加空标题，并说明各自约定。

**验收：**增删改查均有正常与边界测试；排序后仍可按 ID 正确操作；无效输入不改变容器；接口说明返回的指针是否借用。

**参考提示：**剩余 ID 为 1、3，下标通常为 0、1。重复完成可设计为幂等成功或明确返回“已经完成”，但不能重复增加统计计数。

## 第 13 章　文本持久化与 I/O 错误处理

**层级：核心必修。目标：**理解 `FILE *`、打开模式、格式化读写、流错误和关闭；设计可以验证的文本格式；载入失败时保留旧状态。

**项目情境：**通过菜单 7 保存，退出后重新打开程序，再通过菜单 8 读取，任务还在。项目不自动加载或保存，`--file PATH` 只选择数据路径。文件少了一半、字段多了字母或写入失败时，程序能给出有用结果。

```c
FILE *fp = fopen(path, "w");
if (fp == NULL) {
    /* 返回打开失败，保留已有内存状态。 */
} else {
    int failed = fprintf(fp, "CTASK\t1\t%lu\n", list->next_id) < 0;
    if (fclose(fp) != 0) failed = 1;
    /* 即使前面的输出成功，关闭时仍可能发现写入错误。 */
}
```

`"r"` 读已有文件，`"w"` 会截断已有文件，`"a"` 追加；加 `b` 选择二进制模式。`fgets` 逐行读后验证所有字段，不只验证第一个数字。标题若允许分隔符、换行，格式就要转义或编码；更简单的教学格式可以明确拒绝这些字节。格式应有版本，便于未来升级。

本项目的完整首行为 `CTASK\t1\t<next_id>\n`，记录行为 `id\tpriority\tflags\ttitle\n`；`\t/\n` 在文件里是实际制表/换行字节。每行必须以换行结束，读取也接受 CRLF；标题拒绝控制字符，不实现转义。文件里的整数同样只允许数字。实际读行器用 `fgetc` 检查 NUL 和行边界；路径级存储使用 `"rb"/"wb"`，以明确输出协议字节。

载入时先构建临时容器，只有整份文件校验成功才交换进正式容器；半途失败就释放临时容器。这让旧任务不会因为坏文件而丢失。EOF 与错误不同，读取循环结束后看 `ferror`，不要用 `while (!feof(fp))` 驱动读取。

`perror`/`strerror(errno)` 只有在当前接口确实提供有关 `errno` 的错误信息时才有意义；错误码、文件路径、失败阶段要一起记录。ISO C 不保证所有标准库失败都设置 `errno`，需要读具体实现文档。调用其他函数可能改变 `errno`，必要时立即保存。

**预测与动手：**保存、清空内存、重载，比较任务语义；复制一份数据并截断最后一行；对不存在的父目录保存，确认报告失败；检查主项目现在的保存策略。

**验收：**检查写入和关闭结果；文件解析拒绝损坏/重复 ID/超范围字段；载入失败不提交部分结果。直接覆盖保存无法保证断电安全；临时文件、替换、同步与恢复方案属于平台工程专题，不把 `rename` 的跨平台细节假设为完整事务。

**参考提示：**内存比较应逐字段；持久化格式若未保存某个派生统计，应加载后重算它。只有测试过故障分支，才知道“保存成功”的提示是否可信。

## 第 14 章　二进制格式：字节不等于结构体

**层级：工程进阶。目标：**理解文本与二进制流、大小端、版本、长度验证和序列化；能解释为什么不能用结构体内存替代文件协议。

**项目情境：**做一个可选的二进制导出实验，不替换已经稳定的文本格式。目标是自己能描述文件里的每一个字节。

```c
/* 明确要求 8 位字节与 uint32_t 可用的实验环境。 */
unsigned char out[4];
out[0] = (unsigned char)(value >> 24);
out[1] = (unsigned char)(value >> 16);
out[2] = (unsigned char)(value >> 8);
out[3] = (unsigned char)value;
```

`value` 为 `uint32_t`，这段按高字节在前编码一个 32 位数。可以用 `_Static_assert(CHAR_BIT == 8, "8-bit bytes required");` 表达格式前提，并检查实现提供所需类型。解码前把字节转成 `uint32_t` 再移位，避免整型提升后在有符号 `int` 上移位。`fwrite(out, 1, 4, fp)` 返回写成功的元素个数，`fread` 同理；短读/短写必须处理。

`fwrite(&task, sizeof task, 1, fp)` 会混入当前 ABI 的填充、大小端、成员宽度和可能无意义的指针地址。即使同一机器上能读回，也不等于可长期兼容。协议建议包含魔数、版本、记录数、每条记录长度/固定字段定义；读取的长度和数量必须设上限并防止大小乘法溢出。

**预测与动手：**编码 `0x01020304`，写出四个十六进制字节；设计最多 1 MiB 的导入限制；把文件记录数改成极大值，确保在分配前拒绝；用十六进制查看器核对格式。

**验收：**编码与解码对称；损坏长度不能造成越界或巨量分配；未知版本明确拒绝；文件不包含运行时指针。

**参考提示：**四字节为 `01 02 03 04`。把 `"wb"` 改为 `"w"` 在某些系统上可能改变字节解释，二进制格式应明确用二进制模式。

## 第 15 章　算法、复杂度、二分查找与递归

**层级：工程进阶。目标：**根据数据规模选算法；能实现线性查找、一个简单排序、二分查找；理解递归基例和深度成本。

**项目情境：**按优先级展示任务，按 ID 查找任务。业务的原始顺序、排序视图、ID 索引可能有不同要求。

```c
/* 有序 int 数组中寻找 key，区间采用 [lo, hi)。 */
size_t lo = 0, hi = count;
while (lo < hi) {
    size_t mid = lo + (hi - lo) / 2;
    if (items[mid] < key) lo = mid + 1;
    else hi = mid;
}
/* lo < count && items[lo] == key 才表示找到。 */
```

线性查找最坏 `O(n)`；这个二分查找需要数组已按**同一种比较规则**有序，比较次数 `O(log n)`。未排序数据不能直接二分。插入排序最坏 `O(n²)`，适合学习循环不变量和小数组；归并排序可达到 `O(n log n)` 时间但需要额外空间。复杂度是增长趋势，不替代具体测量；标准库 `qsort` 的标准接口不承诺某个算法。

递归把问题缩成更小的同类问题，需要基例。例如任务树节点数等于“1 + 各子树节点数”。每次调用消耗调用栈资源；无限递归或很深的数据链可能耗尽它。阶乘练习必须限制输入并检查乘法溢出，不能用 `factorial(100)` 当作正常 `int` 运算。

**预测与动手：**对 `[2, 4, 4, 7]` 手算 `key = 4` 的 `lo/hi/mid`；实现插入排序，比较已排序与逆序数组移动次数；用递归和迭代分别求 0 到 10 的阶乘，并解释 0 的基例。

**验收：**二分覆盖空数组、首尾、缺失值、重复值；排序的比较器形成一致顺序；递归有基例并说明可接受深度。

**参考提示：**上述二分返回第一个 4 的下标 1。`0! = 1`；使用 `unsigned long long` 也要检查范围，类型变大不会让所有输入都安全。

## 第 16 章　容器专题：链表、栈、队列、哈希与树

**层级：专题选学。目标：**理解不同容器的约束与成本；能选择并实现一个替代容器，而不是把全部结构同时塞进主项目。

**项目情境：**主项目用连续动态数组便于遍历。只有当你能提出具体需求时，再考虑“撤销操作”“待处理队列”“快速 ID 索引”或“子任务树”。

```c
typedef struct Node {
    unsigned task_id;
    struct Node *next;
} Node;
```

这是单链表节点，`next` 借结构标签指向同类对象。已知前驱时插入/删除链接为 `O(1)`，按 ID 寻找仍是 `O(n)`；分配、缓存局部性和指针管理也是成本。删除节点前保存后继，不能释放后再读 `next`。

| 结构 | 在任务工坊中的小实验 | 必须说明的条件 |
|---|---|---|
| 栈，后进先出 | 保存最近 10 次完成操作，实现有限撤销 | 空栈弹出；记录的是 ID 还是完整快照；被删任务如何处理 |
| 队列，先进先出 | 任务进入待执行队列，完成后出队 | 环形数组如何区分空与满；容量变化怎样保持顺序 |
| 哈希表 | 建立 ID 到任务位置的索引 | 冲突、装载因子、扩容；平均近 `O(1)` 需散列等条件，最坏可能 `O(n)` |
| 二叉搜索树 | 根据 ID 输出有序任务 | 普通树可能退化成链；平衡树才可维持对数高度；删除有三种分支 |
| 多叉树 | 表达父任务与子任务 | 无环约束、父子所有权、递归深度、删除整棵子树 |

**预测与动手：**先写链表的创建、插入、遍历、按 ID 删除、完全释放；再任选上表一项。给每个操作写空结构、单元素、多元素测试。把选择理由写成“哪种操作变快，付出了什么”。

**验收：**自己实现的一种容器无泄漏和悬空引用；能手画其状态变化；能解释为何数组已能很好满足当前的小规模列表需求。

**参考提示：**链表删除头节点会改变调用者的头指针，可以返回新头或使用 `Node **head`。哈希索引若存数组下标，删除/排序后必须同步更新索引。

## 第 17 章　预处理、泛型、断言与编译期约束

**层级：工程进阶。目标：**理解对象宏、函数宏、条件编译、字符串化/拼接；优先用类型清楚的函数；分清运行时断言和输入校验。

**项目情境：**用包含保护组织头文件，用编译选项启用调试；用编译期断言表达二进制格式前提。

```c
#define SQUARE_BAD(x) x * x
#define SQUARE_REPEAT(x) ((x) * (x))
static inline int square_int(int x) { return x * x; }
```

`SQUARE_BAD(1 + 2)` 展开成 `1 + 2 * 1 + 2`，结果为 5。加括号能修复结合问题，却不能修复 `SQUARE_REPEAT(i++)` 的重复求值：在 C17 中这里是未定义行为，不能预测合法输出。函数实参只求值一次，但仍需处理算术溢出；宏不是天然更快。

`#if` 处理预处理阶段的条件，不能读取运行时变量。`#` 把宏参数字符串化，`##` 拼接预处理记号；只在确有需要的日志或生成接口中使用。`_Generic`（C11 起）按表达式类型选择关联，例如选取类型对应的函数；不是 C++ 模板，也不让所有类型自动具备同一操作。

`assert(len <= cap)` 检查程序内部约定；定义 `NDEBUG` 时断言可被移除，因此断言表达式里不能放必须执行的写入。用户文件损坏、内存不足等可预期错误必须用普通分支处理。`_Static_assert` 检查编译期常量条件，适合平台假设。

**预测与动手：**手动展开两个宏；用 `#if defined(...)` 控制一条调试日志；用 `_Generic` 为 `int` 与 `double` 选择显示函数；在关闭断言后重跑业务测试。

**验收：**不传带副作用的参数给重复求值宏；宏参数和整体表达式有必要的括号；调试构建与发布构建的业务行为一致。

**参考提示：**`square_int(1 + 2)` 为 9，前提是结果可表示。`assert(add_task(...))` 不合适，关闭断言会把添加操作一起删掉。

## 第 18 章　标准库：会查合同，比背函数名更重要

**层级：核心地图 + 专题选学。目标：**按参数、前置条件、返回值、错误、资源生命周期五项阅读函数说明；认识标准库各家族的用途。

**项目情境：**需要时间戳、关键词搜索、日志或统计时，先判断标准库是否已经提供基础能力。完整头文件清单与后续练习见 [知识路线图](ROADMAP.md#标准库全家族地图c17)。

```c
time_t now = time(NULL);
if (now != (time_t)-1) {
    struct tm *parts = localtime(&now);
    if (parts != NULL) {
        char out[32];
        if (strftime(out, sizeof out, "%Y-%m-%d", parts) > 0) {
            puts(out);
        }
    }
}
```

`time_t` 不保证就是某种整型的 Unix 秒数；日期格式和本地时区是环境的一部分。`localtime` 返回的存储通常可能被后续调用覆盖，不能长期依赖其地址，多线程时还要考虑接口安全性。`clock()` 衡量的是程序使用的处理器时间，不是通用墙上时间秒表。

`<string.h>` 的 `memcpy` 要求源/目标不重叠，可能重叠时用 `memmove`；字符串函数需要合法终止的字符串。`rand` 适合简单教学，不用于密码、令牌或安全 ID；伪随机种子不应每次抽数都重设。`<math.h>` 中的域错误、范围错误要看 `math_errhandling` 等约定；有些工具链链接数学库需要额外参数。

变参函数通过 `<stdarg.h>` 的 `va_list`、`va_start`、`va_arg`、`va_end` 访问参数；数量和类型由接口协议决定，库不会自动知道。`float` 在变参处提升为 `double`，窄整数会发生整型提升。优先练一个受控日志函数，不发明不受约束的“万能参数”。

**预测与动手：**解释 `memmove(a + 1, a, 3)` 为何比 `memcpy` 合适；给时间格式缓冲区设得很小，检查 `strftime` 的失败返回；从路线图选一个标准库家族，写 20 行实验并注明前置条件。

**验收：**调用陌生函数前能找出它的失败信号与资源责任；知道网络、GUI、目录遍历不在 ISO C 标准库中。

**参考提示：**重叠复制是 `memmove` 的职责；日期输出取决于运行时间与时区，不能在测试里写死“今天”。日志函数的格式与实参类型必须一致。

## 第 19 章　测试、调试和未定义行为

**层级：核心必修。目标：**写有意义的边界测试；使用编译警告、断点、调用栈和内存检查；区分不同层次的语言行为。

**项目情境：**“添加两个任务再删除一个”正常，不代表最大长度、空文件或扩容失败也正确。`tests/test_core.c` 是起点，你应解释每个测试保护的行为。

至少区分四种情况：**约束/语法违反**要求实现给出诊断；**实现定义行为**由实现选择并文档化；**未指定行为**有多个允许选择，通常无需说明选择哪种；**未定义行为（UB）**超出标准要求，不能靠某次运行结果推导规律。例子：普通 `char` 是否有符号是实现定义；独立函数实参的求值顺序通常未指定；数组越界、有符号溢出、无效解引用等是 UB。

```c
int numbers[3] = {1, 2, 3};
/* 错误示例，识别即可，不当作正常实验执行： */
/* printf("%d\n", numbers[3]); */
```

编译器不必发现所有 UB。优先打开 README 中的严格警告并逐条理解；支持时用 AddressSanitizer 检查越界/释放后使用，用 UndefinedBehaviorSanitizer 发现一部分 UB。工具受平台、编译器和配置限制，未报告不等于证明安全。

调试步骤：重现最小输入 → 找到第一个错误状态 → 设断点/看调用栈 → 检查对象生命周期与边界 → 修复原因 → 加一个原先失败的回归测试。不要只在崩溃那一行加空判断而忽略上游状态损坏。

**预测与动手：**为添加/删除/加载各列 3 个边界；用调试器在扩容前后观察 `len/cap`；关闭断言再跑一次测试；区分“调用返回失败”和“崩溃”的测试断言。

**验收：**能从失败测试追到具体分支；不把 UB 题目写成确定输出题；测试覆盖成功、失败、资源清理和失败后旧状态。

**参考提示：**`numbers[3]` 是尾后位置，读取不合法。失败后重新列出任务，往往能揭示只检查错误码却没检查状态的测试遗漏。

## 第 20 章　可移植性与 C 的对象模型

**层级：工程进阶。目标：**能识别 ABI、字节宽度、编码、对齐、别名、整数宽度与平台 API 假设；理解 `volatile` 和 `restrict` 的用途边界。

**项目情境：**同一任务文件在两个编译器之间交换；代码从 Windows 搬到 Linux；优化打开后仍应保持符合标准的行为。

`int`、`long`、指针宽度由实现决定，32/64 位操作系统标签不充分说明所有类型。用 `size_t` 表达对象大小，用 `ptrdiff_t` 表达同一数组中合法指针相减的结果，不把地址转成 `int`。对象可能有对齐要求；把任意字节缓冲区强制转成 `Task *` 可能违反对齐、有效类型和对象表示规则。

```c
double value = 1.5;
unsigned char bytes[sizeof value];
memcpy(bytes, &value, sizeof value);
/* 可观察当前实现的对象字节，不能由此定义可移植 double 文件格式。 */
```

字符类型可用于查看对象表示；用不兼容的指针类型去访问对象可能违反有效类型/别名规则，强制转换只改变编译器看到的类型，不让访问自动合法。真正的字节协议要像第 14 章那样定义编码。

`volatile` 告诉实现某些访问具有特殊可观察意义，常见于硬件寄存器；它不提供线程互斥或原子性。`restrict` 是对某段执行中指针访问关系的承诺，违反承诺可能 UB；不要在没理解别名关系时当性能装饰。可变长数组在本项目 C17 基线中不作为必需能力，避免依赖可选支持和不受控栈大小。

**预测与动手：**列出项目中 5 个环境假设；在两个支持的编译器上构建；给二进制实验写清 `CHAR_BIT`、整数宽度、大小端协议和编码前提。

**验收：**能区分 ISO C、编译器扩展、POSIX 与 Windows API；平台假设有检测或文档；不依赖调试版“刚好能运行”的越界行为。

**参考提示：**`#pragma pack` 不能解决指针、大小端或不同类型宽度的文件兼容问题。先写正确的标准代码，测量后再考虑有明确前提的优化。

## 第 21 章　C11/C17/C23 与并发：按需进阶

**层级：专题选学。目标：**知道主项目的 C17 基线包含哪些时代的能力；区分编译模式、编译器支持和运行库支持；初步理解线程、原子与数据竞争。

**项目情境：**主程序保持单线程。完成核心后，另建“后台计数器”或“后台保存”实验，先理解同步再接回业务。

C11 引入 `_Generic`、`_Static_assert`、对齐、线程与原子等能力；C17 主要是修正与澄清。C11/C17 的线程、原子等存在条件支持，检查实现宏与库能力，不能只看编译器接受 `-std=c17`。可核对 [WG14 N1570 的 §6.5.1.1、§6.7.10、§7.17、§7.26](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。

并发实验中的共享计数 `counter++` 是“读、改、写”组合。多个线程未正确同步地访问同一个非原子对象且至少一方修改，可能形成数据竞争并导致 UB。互斥锁保护共享不变量；原子对象只解决对应原子操作及其规定的同步，不自动保护整个任务容器。

```c
/* 选学片段：仅在实现支持标准原子时编译。 */
#include <stdatomic.h>
static atomic_uint finished_count = 0;

/* 工作线程完成一项后： */
/* atomic_fetch_add(&finished_count, 1u); */
```

先用默认顺序一致原子操作理解正确性，再研究 acquire/release、relaxed、happens-before；不要从“lock-free 更快”开始。`volatile` 不能代替原子。标准线程的创建、连接、互斥和条件变量分别见 `<threads.h>`，需要检查返回状态并保证线程结束前资源仍有效。

C23 增加了 `nullptr`、`constexpr` 对象、`typeof`、`_BitInt`、属性及 `<stdbit.h>`、`<stdckdint.h>` 等内容；这是一条迁移选学路线，不能直接混入本项目 C17 源码。语言与库支持分别验证。特性清单可对照 [WG14 N3096 的附录 M.2 与库目录](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf)，草案用于查阅，不等同于手里的正式标准文本。

**预测与动手：**解释两个线程各加一万次为什么不能靠“最终数看起来对”证明无竞争；用原子计数或互斥版本验证精确结果；把一个 C23 特性写成独立小程序并记录所用工具链，不改主项目基线。

**验收：**能给共享数据标出锁/原子规则；不在线程仍运行时释放它借用的内存；知道课程没有把并发实验自动实现进主程序。

**参考提示：**最终应为 20000；先确保两个线程都成功创建和连接，再读取结果。保存线程还涉及任务快照、文件一致性、退出协调，远超一个原子计数器。

## 第 22 章　毕业改造：独立完成一个可交付功能

**层级：综合验收。目标：**从需求到接口、实现、测试、文档走完整闭环；建立“我知道什么、还有什么要查”的边界。

**项目情境：**从以下项目任选一个，完成后再选下一个。不要同一轮修改所有模块。

1. **标签与筛选。**每项最多 3 个标签；定义标签长度单位、重复规则与持久化版本；验收空标签、最大数量、中文与分隔符。
2. **撤销最近操作。**用栈保存必要快照；定义删除、重复撤销与退出后是否保留；验收连续 10 次操作和容量耗尽。
3. **子任务。**用树表达层级；禁止环；定义完成父任务与删除子树策略；验收深层输入和全部释放。
4. **导出报表。**导出文本或 CSV；正确处理逗号、引号、换行；把显示格式与内部数据分开；验收导出失败与再次打开。
5. **可替换存储。**保留业务接口，为文本和二进制后端写同一组往返测试；明确格式版本和失败后状态。

开始写代码前，只写一页设计：输入是什么、输出是什么、哪些情况失败、内存归谁、旧文件怎样处理、最小成功样例和最小失败样例各是什么。实现时保持模块边界，添加失败分支再写回归测试。

**预测与动手：**提交一份可复现的演示：从空目录启动、添加任务、触发一个错误、保存、退出、重载、证明数据一致。再找一处你过去写得不清楚的代码，改进命名/接口并说明理由。

**验收清单：**

- 从干净的构建目录可编译，严格警告已处理或有具体解释。
- 成功、边界、非法输入和 I/O 失败均有测试；失败后状态符合约定。
- 每块资源有明确所有者，退出清理完整；支持时跑过内存检查。
- 文件格式、编码、容量限制与平台前提可被另一个人读懂。
- 能不看代码讲清一条命令穿过的模块、一次扩容和一次失败加载。
- 能解释一个取舍：为什么选数组/链表、文本/二进制、错误码/退出中的某一种。

**参考提示：**没有唯一参考实现。好答案能通过别人根据需求写出的测试，并能解释失败路径。若只能复述现有代码，先合上代码，在空文件里重写一个最小版本，再回来比较。

## 复习时的三条主线

**数据主线：**类型 → 数组/字符串 → 指针 → 结构体 → 动态容器 → 算法。每前进一步，都继续回答“有效范围在哪里”。

**执行主线：**编译/链接 → 控制流 → 函数/模块 → 错误处理 → 测试/调试。每前进一步，都继续回答“失败时谁知道、谁处理”。

**资源主线：**对象生命周期 → 内存所有权 → 文件句柄 → 临时状态 → 并发实验。每前进一步，都继续回答“谁负责结束这段生命周期”。

遇到混淆时查 [常见误区与术语](GLOSSARY.md)，需要选择下一步时查 [知识覆盖与分阶段计划](ROADMAP.md)。课程里明确写“实验/选学”的部分是需要你继续实现的任务，不能据此认为主程序已经提供这些功能。
