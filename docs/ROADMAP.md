# 知识覆盖、练习路线与学习计划

本路线以 **C17、宿主环境、标准库命令行程序** 为主线。宿主环境通常有操作系统和标准库；嵌入式的独立环境可能有不同启动方式与库支持，不能直接套用本项目所有假设。

“学会”分三层，不把文档里出现过的内容都算成已经实现：

- **项目实现**：可到主程序源代码查到、运行、测试的行为。
- **课程覆盖**：有解释、例子、练习和验收，但可能由你在独立实验中实现。
- **后续专题**：明确指出边界和第一步，不宣称一套 CLI 已覆盖相应领域。

先按 [课程第 1 章](COURSE.md#第-1-章让程序真正运行源文件编译链接) 开始；实际命令看根目录 `README.md`，渐进入口看 `START_HERE.md`，业务阅读看 `PROJECT_GUIDE.md`。Markdown 阅读器的中文标题锚点规则可能不同，链接跳转不支持时直接按章号查找。

## 主项目已经承载的知识

以下是读源代码的检查任务，真实接口以头文件为准。

| 主线 | 当前项目的落点 | 你必须能解释的问题 |
|---|---|---|
| 数据模型 | `Task` 有 `unsigned long id`、`char title[96]`、优先级与 flags | 标题最多容纳 95 字节内容加终止符；中文个数不是字节数；低/普通/高分别是 1/2/3。 |
| 状态位 | done 掩码为 1（第 0 位），urgent 掩码为 2（第 1 位）；通过模块接口修改 | 为什么清除 done 位不能把 urgent 位也清掉？如何拒绝未知位？ |
| 动态容器 | `TaskList` 的 `items/len/cap/next_id`，初始化、增长、清理 | 元素有几个？分配了几个槽位？谁拥有缓冲区？借用指针何时失效？ |
| 业务接口 | 添加、查找、删除、完成/紧急、排序、遍历回调、状态文本 | ID 为什么不能当下标？删除/排序怎样改变位置？回调允许做什么？ |
| 输入 | `input.c` 的行读取与数值解析 | 长行是否消费完？数字后有垃圾怎么办？EOF 与格式错误的路径是否不同？ |
| 文本存储 | `storage.c` 的流级 `task_write/read` 与路径级 `task_save/load` | 哪一层拥有并关闭 `FILE *`？失败载入为什么不替换原列表？ |
| 文件格式 | `CTASK\t1\t<next_id>\n`，记录为 `id\tpriority\tflags\ttitle\n` | 每行要求换行，接受 CRLF；字段怎样验证？标题为什么不能包含分隔符或换行？ |
| 可靠性 | 核心测试、明确错误返回、临时加载容器 | 分配/解析失败后如何清理？原任务是否保留？怎样测试这些约定？ |
| 交互与工具 | 菜单、`--demo`、`--file PATH`、`--help` | 示例演示与正式保存的区别是什么？`--file` 选择路径，菜单保存/加载才做相应 I/O。 |

当前保存以打开文件直接写入为基础；读取在全部成功后提交。**读取的事务式替换不等于保存具备断电事务保证**。原子替换、文件锁、同步到稳定存储等要在后续平台专题中设计。

## 标准库全家族地图（C17）

这里列出 C17 的 29 个标准头文件及用途。**表中实验大多是后续任务，主程序没有为了“用全库”强行加入这些能力。**先学项目实际需要的 I/O、字符串、内存和错误；其余按需求查阅。函数合同包含前置条件、返回值和失败行为，不能只背名字。

| 头文件 | 用途与正确关注点 | 对应章节或下一步实验 |
|---|---|---|
| `<assert.h>` | 运行时断言与 `NDEBUG`；断言会被关闭，不承担输入验证 | 17、19：关闭断言重跑测试，确认业务仍执行。 |
| `<complex.h>` | 复数运算，存在条件支持；分支切线和数值误差属于数学语义 | 18 选学：求复数模与共轭，用容差核对。 |
| `<ctype.h>` | 字节字符分类/转换，参数须为 EOF 或 unsigned char 可表示值；不是 Unicode 字符分类库 | 6：安全跳过尾部空白，测试高位字节。 |
| `<errno.h>` | 某些函数的错误指示，使用前需了解具体函数约定 | 6、13：给 `strtol` 清零并检查 `ERANGE`；别用旧 errno 解释成功调用。 |
| `<fenv.h>` | 浮点异常标志和舍入环境；实现能力与编译选项会影响使用 | 18、20 选学：按实现文档观察一次浮点域/范围错误。 |

| `<inttypes.h>` | 固定/最大宽度整数的格式宏与转换函数 | 2、14：用 `PRIu32` 一类宏打印支持的对应类型。 |
| `<iso646.h>` | `and/or/not` 等替代记号宏 | 3、17 选学：把一个逻辑表达式改写后比较；阅读旧代码时能识别。 |

| `<wctype.h>` | 宽字符分类与映射，受区域设置等约束 | 5、18 选学：与 `<ctype.h>` 比较；完整 Unicode 处理仍需专用方案。 |

附录中的浮点绑定、边界检查接口（Annex K）和可分析性等有各自条件，并非所有实现提供。`strcpy_s` 等带 `_s` 名字的函数不是本项目可移植基线的必需依赖。POSIX 的 `getline`、`strdup`（在 C17 基线下）、`pthread_*`，Windows 的 `Sleep/CreateFile` 等也不能因为某台机器可用就称为 C17 标准库。

## 用标准资料核对进阶事实

不要把标准草案当作第一本入门书。先完成实验，有具体问题再查条款。以下是官方 WG14 的公开资料入口，属于对应版本的草案或工作文件，不替代正式发布文本：

- [N1570：C11 委员会草案](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)：语言与库条款入口，第 6 章查类型/表达式，第 7 章查库，附录 B 查库总览。
- [N3096：C23 工作草案](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf)：附录 M 的版本历史有助于区分 C11、C17 和 C23；其 §7.18/§7.20 可查新增位操作与受检整数运算家族。课程主项目仍编译为 C17。
- [WG14 文档目录](https://www.open-std.org/jtc1/sc22/wg14/www/docs/)：定位提案和草案；一个提案存在不自动意味着它已进入你所用版本的标准。

学习记录建议保存三个证据：最小代码、实际构建命令、适用前提。讨论某个结果时附上这些信息，比只说“C 就是这样”更可靠。
