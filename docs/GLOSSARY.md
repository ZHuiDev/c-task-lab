# 常见误区与术语：按问题查阅

遇到问题先找到最接近的一条，再回到 [课程](COURSE.md) 做对应实验。本词典不要求你第一天全部读完。

## 第一组：程序为什么没按预期运行

| 术语 / 常见想法 | 更准确的理解 | 回去做什么 |
|---|---|---|
| 源文件与可执行文件：“我改了代码，为什么输出没变？” | `.c` 是构建输入，可执行文件是构建输出；必须重新成功构建，并确认运行路径。旧程序仍可能留在目录里。 | 第 1 章：改一条输出，重建后验证；记录构建失败时你运行了哪个文件。 |
| 编译与链接：“函数在另一个文件里，为什么还报错？” | 编译需要兼容的声明；链接需要唯一的可用定义。包含头文件不等于把实现链接进来。 | 第 11 章：暂时漏掉一个 `.c` 的链接，再恢复。 |
| 声明与定义：“写了函数原型就实现了吗？” | 原型描述函数类型，定义提供函数体。对象声明也可能不是定义，例如头文件中的 `extern`。 | 第 4、11 章：在两个源文件之间调用一个函数。 |
| 头文件保护：“有保护宏就不会重复定义了？” | 它防止同一翻译单元反复展开同一头文件；普通外部函数仍不能在多个翻译单元各定义一次。 | 第 11 章：头文件放声明，源文件放普通函数定义。 |
| 警告：“能生成 exe 就是对的？” | 警告可能暴露格式不匹配、截断、未初始化等真实缺陷；实现不必发现全部非法行为。 | 第 19 章：解释并修复每条警告，不用强制转换一概压掉。 |
| 优先级与求值顺序：“乘法优先，所以右边一定先执行？” | 优先级决定语法结合关系，不普遍决定操作数执行顺序；`&&` 等少数运算符另有顺序/短路保证。 | 第 3 章：把有副作用的子表达式拆成独立语句。 |
| 未定义行为 UB：“我的电脑输出 3，所以答案是 3？” | UB 不受标准结果约束，换优化级别或环境可能改变所有表现，不能给它指定可靠输出。 | 第 19 章：识别越界、无效指针、有符号溢出和未序列修改；先修复再观察。 |
| 实现定义与未指定：“不确定就都是 UB？” | 实现定义要求实现记录选择；未指定允许在若干合法结果中选择；两者都不同于 UB。 | 第 19—20 章：比较普通 char 的符号性与独立函数实参的求值顺序。 |

## 第二组：数字、文本和输入

| 术语 / 常见想法 | 更准确的理解 | 回去做什么 |
|---|---|---|
| 类型：“变量名叫 count，所以它不会负数？” | 名字不约束值，类型范围与业务范围也不同；优先级即使能存 100，也不代表 100 合法。 | 第 2、6、12 章：把解析范围与业务验证分别写出。 |
| 整数除法：“接到 double 里就有小数？” | 运算根据操作数类型先发生；`double x = 2 / 3;` 得到 0，再转成 0.0。 | 第 2 章：把转换移到除法前。 |
| 强制转换 cast：“写 `(int)` 就安全了？” | 转换只请求某种类型结果，不检查业务范围，也不修复越界、对齐或生命周期问题。 | 第 2、20 章：先验证范围，再转换；删除用来掩盖类型错误的转换。 |
| 无符号：“unsigned 能自动防所有负数错误？” | 负数可能在转换后变成很大的无符号值；减法也可能取模回绕。 | 第 2 章：解释 `-1 < 1u`，给 `len - 1` 加非空前提。 |
| 溢出：“C 的整数都像一个环？” | 无符号按范围取模；有符号溢出通常是 UB；两者还都可能违背业务需求。 | 第 10、15 章：在容量乘法、ID 自增和阶乘前检查范围。 |
| 浮点：“显示 0.3 就代表值精确等于 0.3？” | 格式化输出可能舍入；很多十进制数无法被所用二进制浮点精确表示。 | 第 2、18 章：输出更多有效位；根据需求定义容差或改用整数单位。 |
| 格式说明符：“%d 能打印所有整数？” | 格式化变参接口依赖匹配的类型；`size_t` 用 `%zu`，`unsigned long` 用 `%lu`，指针用 `%p` 加 `(void *)`。 | 第 2、7 章：检查每个 printf 的实际实参类型。 |
| 字符数组与字符串：“char 数组都能 puts？” | 只有在可访问范围内存在终止零的字节序列才是这里所说的 C 字符串。 | 第 5 章：画出内容与 `\0`，用非字符串数组解释边界风险。 |
| `sizeof` 与 `strlen`：“都能得到长度？” | 前者给对象或类型的字节大小；后者扫描字符串到首个零，不计零本身。函数里的数组形参实际是指针。 | 第 5 章：比较数组对象与函数形参的 `sizeof`。 |
| UTF-8：“title[96] 可以存 96 个汉字？” | 它只有 96 个 C 字节，需留终止符；本项目最多 95 字节内容。UTF-8 的码点可占多个字节，屏幕字符还可能由多个码点组成。 | 第 5 章：测试一组中英文混合标题；说明限制单位，不按字节切断字符序列。 |
| 字符串比较：“两个文本用 == 比较？” | 数组转换/指针的 `==` 比较地址；内容比较通常用 `strcmp`，它返回负/零/正而非保证只返回 -1/0/1。 | 第 5 章：让内容相同但不同数组的字符串参与比较。 |
| `strncpy`：“带 n 就一定有终止符？” | 源长度达到 n 时可能不写终止零；它还有填充语义，不能不看合同当安全复制通用解。 | 第 5 章与字符串练习：检查容量后复制，并明确失败策略。 |
| `strtol`：“得到 12 就说明输入合法？” | `12abc` 也可转换出前缀 12；需检查结束指针、范围、剩余字符与业务规则。 | 第 6 章：依次输入空串、空白、负数、垃圾后缀与超大数。 |
| EOF：“按回车就输入结束？” | 空行是一次有效读取；EOF 表示输入流结束。`fgetc` 结果应先放 int，才能区分全部 unsigned char 值与 EOF。 | 第 6、13 章：从文件重定向读取；用返回值控制循环。 |
| `errno`：“非零说明刚才一定失败？” | 它可能是旧值；只有特定函数按约定设置它。先看函数返回值，必要时调用前清零并在失败后立刻保存。 | 第 6、13、18 章：比较一次超范围和一次成功的 strtol 调用。 |

## 第三组：指针、对象和内存

| 术语 / 常见想法 | 更准确的理解 | 回去做什么 |
|---|---|---|
| 对象：“只是变量的另一种叫法？” | C 对象是可存放值的存储区域，可有名字，也可来自分配；表达式值、类型和对象是不同概念。 | 第 2、7、10 章：给数组元素、指针变量和 malloc 对象分别画框。 |
| 数组与指针：“数组就是一个指针变量？” | 数组有自己的元素存储，不能整体赋值；很多表达式会把数组转换为首元素指针，例外包括对数组对象的 sizeof 等。 | 第 5、7 章：比较数组大小与指针大小，别从常见数值推导标准保证。 |
| 指针解引用：“地址是数字，随便加就能访问？” | 地址值有效还不够，要指向仍活着、类型和对齐合适、可访问范围内的对象。算术也有同数组边界要求。 | 第 7、20 章：为每次 `*p` 写出所指对象与前提。 |
| 尾后指针：“可以形成就可以读取？” | 数组尾后指针可作为合法边界，但解引用不合法。空数组接口还需约定何时允许空指针。 | 第 7、15 章：用 `[lo, hi)` 区间写循环与二分查找。 |
| 空指针 NULL：“指向地址 0 的普通对象？” | 空指针值用于表示未指向对象/函数；表示方式由实现决定，不能解引用，也不应猜测其位模式。 | 第 7、10 章：明确查找失败返回空时调用者怎样处理。 |
| 悬空指针：“free(p) 后 p 变量还在，所以还能用？” | 指针变量还存在不表示目标对象还存在；释放后对象生命周期结束。其他别名也随之失去有效目标。 | 第 7、10 章：画释放前后两个指针指向同一块内存的情形。 |
| 值传递：“传指针就不是值传递？” | 指针值本身也复制给形参；通过副本可修改共同指向的对象，改变形参指向不会直接改变调用者的指针变量。 | 第 4、8 章：用 `T **` 或返回新指针更新调用者。 |
| `const`：“加 const 就永远不可变？” | const 限制通过该类型路径的修改；不延长生命周期，不自动同步，也不总是 C17 整型常量表达式。 | 第 7、17 章：分别解释 `const int *p` 与 `int *const p`。 |
| 所有权 ownership：“C 会在离开函数时自动 free？” | 普通动态分配不会自动释放；项目必须约定拥有者、借用者和转移规则。局部指针消失也可能留下泄漏。 | 第 10、12 章：逐资源标注谁释放、何时释放。 |
| `len` 与 `cap`：“分配了 8 个槽就有 8 个任务？” | cap 是存储能力，len 才是有效任务数；通常仅 `[0, len)` 可当任务读取。 | 第 10、12 章：添加第 1 项时画出已用与未用槽位。 |
| `realloc`：“返回 NULL 时旧块也没了？” | 对本项目使用的非零新大小，失败保留旧分配；成功后用新返回值，旧别名不可继续依赖。 | 第 10 章：临时变量接收；新地址成功后才提交。 |
| 浅拷贝：“结构体赋值会复制整个对象图？” | 结构成员的值会复制，指针成员仍指同一目标；需要独立资源时自己设计深拷贝。嵌入字符数组则作为成员被复制。 | 第 9—10 章：对比固定数组标题与 `char *` 标题。 |
| ID 与下标：“ID 是第几项？” | ID 是身份，下标是当前存放位置；删项、排序、重建索引会改变位置，不能悄悄改变身份。 | 第 12、15 章：删除中间项后保留剩余 ID，再按 ID 查找。 |
| 借用地址：“find 返回值可以一直保存？” | 其有效期受容器修改约束；扩容可能改变地址，删除/排序可能改变地址对应的任务。 | 第 7、12 章：长期保存 ID，修改容器后重新 find。 |
| 对齐与填充：“结构体大小就是成员相加？” | ABI 可能插入空隙满足对齐；填充不代表业务数据，不能由 memcmp 结果定义结构体语义相等。 | 第 9、14、20 章：打印偏移，按字段比较。 |
| `void *` 与函数指针：“通用指针就是万能容器？” | void* 适合对象指针的通用接口；不保证可作为函数指针的可移植替身。类型、对齐和生命周期前提仍在。 | 第 8、20 章：为回调写精确签名，别用 cast 压掉不匹配。 |
| 二维数组：“int a[2][3] 可以传 int**？” | 前者是连续的行数组，转换后为指向一行的指针；后者指向指针对象，两者布局不同。 | 第 8 章：画两种图；让编译器核对形参类型。 |

## 第四组：文件、算法与进阶边界

| 术语 / 常见想法 | 更准确的理解 | 回去做什么 |
|---|---|---|
| 文本序列化：“写得出来就能一直读？” | 格式要定义版本、字段、分隔、转义/拒绝规则、范围和终止方式；否则升级和坏数据都难处理。 | 第 13 章：给 CTASK 文件逐字段解释，再制造损坏样本。 |
| 二进制序列化：“fwrite 一个 struct 最简单？” | 能输出内存，不代表形成稳定协议；填充、大小端、类型宽度、指针会破坏兼容。 | 第 14 章：明确编码 0x01020304 的四个字节。 |
| 事务式加载：“失败时能把已读内容留下来？” | 本项目约定整份验证成功才替换旧容器；留下半份会破坏调用者对失败不变的预期。 | 第 13 章：加载中间损坏的文件，随后列出原任务确认未变。 |
| 保存成功：“fprintf 没报错就保存完了？” | 缓冲可能推迟错误，关闭结果仍需检查；直接写文件不提供完整断电事务保证。 | 第 13 章：检查打开、写入、关闭；认识平台持久化专题的边界。 |
| `feof`：“先检查一下就知道还能不能读？” | EOF 指示通常在一次读取尝试遇到末尾后才设置；应由实际读取返回值控制循环，再区别 EOF/错误。 | 第 13 章：读最后一行和空文件，各数一遍处理次数。 |
| `assert`：“可以用来检查用户输入？” | 断言用于开发期内部约定，可能整体移除；输入错误和分配失败要正常处理，且断言内不放必需副作用。 | 第 17、19 章：打开 NDEBUG 后复查行为。 |
| 复杂度 O(n)：“就是执行 n 毫秒？” | 它描述随规模增长的趋势并隐含操作模型；常数、缓存、分配与输入分布仍影响实测。 | 第 15—16 章：先数比较/移动，再用真实规模计时。 |
| 二分查找：“比遍历快，哪里都用？” | 要先有符合相同比较规则的有序数据；维护顺序本身有成本，链表也不提供数组式中点随机访问。 | 第 15 章：无序数据先排序，保留重复值边界测试。 |
| 哈希表：“查找必定 O(1)？” | 典型设计在散列与装载等条件良好时平均常数，冲突严重时可能退化；扩容和删除规则仍需设计。 | 第 16 章：构造大量碰撞，验证冲突处理。 |
| 递归：“写出递归式就肯定终止？” | 必须有可达基例，每次缩小问题；调用深度有限，且中间结果仍可能溢出。 | 第 15—16 章：列出递归深度上限与迭代替代。 |
| `volatile`：“保证线程都看见就是线程安全？” | 它不提供原子读改写、不提供互斥，也不使数据竞争合法；同步用合适的锁/原子规则。 | 第 20—21 章：先用标准原子计数器，再研究内存顺序。 |
| 原子：“把 len 设原子，整个数组就安全了？” | 容器有多个字段和元素之间的不变量，单个原子变量不能自动保护扩容、释放和一致快照。 | 第 21 章：画后台保存与主线程扩容的资源时序。 |
| 标准 C 与扩展：“我的编译器支持就属于 C17？” | 编译器可能默认接受扩展；标准模式、警告选项、运行库和平台 API 都应明确。 | 第 20—21 章：在严格模式构建，记录每个非标准依赖。 |
| C23：“新特性可以顺手写进 C17 项目？” | 新语言和库特性需要对应实现；试验独立编译，主项目基线和构建说明必须保持一致。 | 第 21 章：任选一个特性，记下编译模式、编译器、库与能力检测。 |

## 排错时按这个顺序提问

1. **运行的是新程序吗？**看构建是否成功、输出路径是否一致。
2. **最小输入是什么？**从一条命令、一个元素、一行文件复现。
3. **哪个状态第一次错了？**先查长度、容量、索引、返回值，不只盯崩溃行。
4. **这个对象还活着吗？**查局部返回地址、扩容、删除、释放、别名。
5. **接口合同满足了吗？**查字符串终止、容量、格式类型、排序前提、文件模式。
6. **失败分支有没有清理和保留旧状态？**把资源与提交点画出来。
7. **能留下回归测试吗？**修复后用原输入验证，再补最接近的边界。

如果还不能解释原因，把相关代码缩成一个独立小程序，并带上编译命令和实际输入。能精确描述问题，本身就是 C 工程能力的一部分。
